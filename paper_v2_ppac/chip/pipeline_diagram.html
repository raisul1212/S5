Mambino paper · v2 chip PPAC · pipeline block diagram (v2)

From training checkpoint to per-config chip energy — every number traceable

Open-source pipeline. Every stage's input is a previous stage's output; nothing is transcribed by hand. Reviewers can reproduce end-to-end from the training checkpoint.

JAXPR extraction Chip spec (Python source of truth) Energy model (Accelergy + CACTI + NeuroSim) Dataflow model (Timeloop) Cross-check (SCALE-Sim) Input / output artifact
Phase 1

Extract workload from trained checkpoint

JAX/Flax model rebuilt from training code; JAXPR walked; per-op records emitted.
Invariant status All 5 configs pass. Corner 1 (188K): walker = emitter = 882,903,552 dot_general FLOPs, 65,766,556 elementwise FLOPs, bit-for-bit. Emitted files: workload_<cfg>_{gemms.csv, gemms.yaml, elemwise.yaml, manifest.yaml}.
Phase 2

Chip specification — single Python source of truth

One dict → three consistent formats. Prevents silent drift between tools.
Tooling caveat Timeloop's YAML parser triggers std::bad_alloc on our nodes: arch. arch_mambino.cfg (libconfig, same chip params) is the working substitute. Documented in paper_v2_ppac/chip/README.md.
Phase 3

Per-access energy modeling — Accelergy 0.4

CACTI 7 + NeuroSim primitives produce validated per-component energies at 22 nm INT8.
Phase 4

Dataflow model — timeloop-model per GEMM

Explicit WS mapping → cycles + per-component energy. No mapper search (fixed dataflow has one legal mapping).
Phase 5

Aggregate per-config chip PPAC

Sum per-GEMM energy × repeat count from the workload manifest to get per-config totals.
Phase 6

Independent cross-check — SCALE-Sim on same workloads

Same JAXPR-extracted GEMMs, a different tool, a different energy model. Cross-tool agreement establishes robustness.
Cross-tool contract Cycle counts must agree within ~20% (accounts for analytical vs cycle-accurate modeling differences). Memory-traffic access counts must agree within an order of magnitude. Bigger disagreement flags a bug in one of the tools.
Phase 7

Paper artifacts — rewrite §6/§7/§8, redo Fig 4, tag mambino-paper-v2

Every number in the paper's chip section traces back through this pipeline to a training checkpoint.

Traceability contract. Every number in the paper's §6/§7/§8 traces: paper number → timeloop-model.stats.txt → arch_mambino.cfg + mapping.yaml + ERT.yaml → workload_<cfg>_gemms.yaml → JAXPR walker totals → training checkpoint on PURR 10.4231/9ADT-WP13 → git tag mambino-paper-v1.
